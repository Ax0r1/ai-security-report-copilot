# Contributing

Thanks for helping improve this project. Start with an issue that explains the use case, then keep pull requests focused, tested, and documented. Security reports must follow [SECURITY.md](SECURITY.md) rather than a public issue.

Use only synthetic fixtures or systems you own or are explicitly authorized to assess. Never commit credentials, private logs, target identifiers, or generated artifacts containing sensitive data.

Before opening a pull request, run the documented test and lint commands locally and describe the behavior you verified.
